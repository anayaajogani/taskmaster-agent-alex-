# Product Requirements Document: **StudyAgent**
**Track:** TaskMaster (Agentic Student Coordinator)  
**Status:** Updated for Hackathon Submission  

---

## 1. Vision & Purpose
Current student tools (Canvas, Ed, Gradescope) are passive data silos. Students spend 30% of their "study time" just figuring out *what* to study and *where* the files are. 

**StudyAgent** is an autonomous executive assistant that transforms passive academic data into an active roadmap. It doesn't just list deadlines; it protects the student's time, prioritizes high-impact tasks, and bundles resources so the student can achieve "Flow State" instantly.

---

## 2. Core User Personas
*   **The Overwhelmed Bear (UC Berkeley Student):** Taking 4 techs, involved in 2 clubs, and recruiting. Has the data but lacks the "bandwidth" to organize it.
*   **The Procrastinator:** Needs a low-friction "On-Ramp" to start big assignments.

---

## 3. Key Agentic Features (TaskMaster Alignment)

### Feature 1: The Autonomous Time-Blocker (Scheduling)
*   **What it does:** The agent monitors Canvas and Course Sites for new assignments. It uses Gemini to analyze the "Complexity/Spiciness" of a task (e.g., a "Project" is high-effort; a "Quiz" is low-effort). 
*   **Agentic Action:** It autonomously scans the user’s Google Calendar and **injects "Study Blocks"** into free gaps before the deadline. If a student adds a social event, the agent re-evaluates and shifts the study block to the next optimal gap.
*   **Long-Running Logic:** This operates throughout the 15-week semester, maintaining an evolving "Balance of State" between academic load and free time.

### Feature 2: The "Executive Briefing" (Daily/Weekly Synth)
*   **What it does:** Instead of a list of raw notifications, the agent synthesizes Ed Discussion staff posts and Canvas updates into a cohesive narrative.
*   **Agentic Action:** At 8:00 AM daily, the agent sends an email briefing. It cross-references assignments with staff activity.
*   **Example Output:** *"Good morning. You planned to start HW3 today, but the TA posted on Ed 2 hours ago that there's a typo in the starter code. I've moved your HW3 block to tomorrow and moved up your 'Review Lecture 4' task instead."*

### Feature 3: The "Deep Work" Resource Bundler (Task Manager)
*   **What it does:** Solves the "5-tab tax." 
*   **Agentic Action:** When a student marks a task as "In Progress," the agent autonomously gathers a **Bundle**: the assignment PDF, the relevant discussion worksheet, the specific lecture slide deck, and any Ed threads tagged "Staff Clarification."
*   **Task Breaker:** It breaks "Do Project 2" into atomic steps (e.g., "Step 1: Implement the `HashMap` constructor") based on the spec’s text.

## 4. UI/UX Design Principles

### A. The "Focus" Dashboard
*   **The Timeline:** A unified, vertical chronological feed. It doesn't just show deadlines; it shows **Events** (e.g., "Study Session Blocked by Agent") interspersed with **Deadlines**.
*   **Priority Heatmap:** Tasks are color-coded not just by "Subject," but by **Urgency x Spiciness**. A high-weight project due in 2 days glows differently than a participation quiz.

### B. The "Bundle" View (The UX "Wow")
*   When clicking a task, a drawer slides out.
*   **Left Column:** The "Atomic Steps" generated by the agent with checkboxes.
*   **Right Column:** "Your Context Library" — a curated list of links/files the agent pulled specifically for *this* task. No searching required.

### C. The "Agent Reflection" Log
*   To satisfy the TaskMaster "proof of work" criteria, a small console area shows the agent's recent autonomous decisions:
    *   *LOG:* "Detected new staff post on Ed #402. Identified as 'Policy Change' for HW2. Updating briefing..."
    *   *LOG:* "Canvas deadline for 'Lab 3' changed. Re-scheduling study block on user calendar..."

## 5. User Journey (The Winning Demo Script)

1.  **Onboarding:** User pastes their Canvas/Ed tokens into a clean, minimalist Wizard.
2.  **The "Sync":** The screen shows the Agent "Thinking" (Vertex AI processing).
3.  **The Result:** The dashboard populates. The student notices that their Google Calendar (synced in the UI) already has three "Study Blocks" for a project they didn't even know was posted yet.
4.  **The Interaction:** The student clicks "Start Task." The UI instantly presents the "Bundle" — the spec PDF and the TA's Ed post about the rubric change appear side-by-side.
5.  **The Briefing:** The user opens a simulated "Morning Briefing" email that demonstrates the agent's ability to prioritize and advise on "What to skip" based on staff feedback.
